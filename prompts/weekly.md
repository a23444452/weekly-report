# 週報摘要 Prompt 模板

> 此模板由 /weekly-report skill 使用：Claude 讀取 `data/raw-activity.json` 與上週報告後，
> 依以下規則生成週報 Markdown。可依主管口味直接編輯本檔調整。

## 生成規則

1. **語言與口吻**：繁體中文台灣用語，業務語言優先於技術語言。
   「修正 race condition」→「解決了 X 功能偶發性失敗的問題，提升穩定性」。
   保留必要的技術名詞（系統名、模組名），但避免 commit message 式的流水帳。
2. **以 merged MR 為主要素材**：一個 MR 通常是一件完成的事。多個 MR 屬於同一件事時合併敘述。
   commits 只用來補充 MR 沒涵蓋的工作。
3. **對照上週承諾**：拿上週報告的「下週計畫」逐項對照——完成的放進本週成果並標註，
   未完成的放進「進行中」或「風險與阻礙」，並簡述原因。不可默默略過。
4. **量化**：能寫數字就寫數字（處理了 N 個 issue、涵蓋 N 個模組）。
5. **誠實**：raw data 裡沒有的事不要編造。資料太少的專案就如實寫「本週無進展」。

## 輸出格式

```markdown
# 週報 {week_start} ~ {week_end}

## 本週成果

### {專案名稱}
- {成果描述}（對應上週計畫 ✓ / 新增項目）
- ...

## 進行中

- {項目}：{目前狀態、預計完成時間}

## 風險與阻礙

- {阻礙描述}：{影響、需要的協助}
（沒有就寫「無」）

## 下週計畫

- {計畫項目}（此段落留給使用者審稿時補充，先依 opened issues 與進行中項目起草）
```

## 頁數提示（給 PPT 階段）

週報 PPT 目標 5-8 頁：封面、本週成果總覽、各專案 1 頁（僅有實質進展的專案）、
風險與下週計畫合併 1 頁。在 Markdown 開頭不需要寫這些，PPT_Generator 的大綱階段會自行分頁。
